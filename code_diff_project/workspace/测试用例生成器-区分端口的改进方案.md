# 测试用例生成器 - 区分端口的改进方案

## 问题分析

### 当前问题
从图片中可以看到，生成的测试用例标题是：
- "UI测试 - 融资还款菜单 - 正常分页查询"
- "UI测试 - 融资还款菜单 - 带查询条件分页查询"

**问题**：测试用例没有明确标注是哪个端（供应商端SPY、资金方端CPT、核心企业端CE），导致测试人员无法明确知道应该用哪个账号登录、访问哪个菜单。

### 实际情况
同一个API `POST /order-scfPc-web/ofRepayment/paymentManagementPage` 被多个端的页面调用：

1. **供应商端（SPY）**：
   - 菜单名称："还款管理"
   - 路由：`/orderPaymentManageBook`
   - 页面组件：`orderPaymentManageBook.vue`

2. **资金方端（CPT）**：
   - 菜单名称："还款管理"
   - 路由：`/orderPaymentManageBookCPT`
   - 页面组件：`orderPaymentManageBookCPT.vue`

3. **核心企业端（CE）**：
   - 菜单名称："融资还款"
   - 路由：`/orderPaymentManageBook`
   - 页面组件：`orderPaymentManageBook.vue`
   
   - 菜单名称："付款管理"
   - 路由：`/paymentManagementCE`
   - 页面组件：`paymentManagementCE.vue`

## 改进方案

### 方案概述
需要在测试用例生成流程中增加"端（端口）识别"功能，让生成的测试用例明确标注是哪个端。

### 需要修改的代码位置

#### 1. **数据收集阶段** - 识别端信息

**位置**：收集API调用信息的代码（需要找到调用 `generate_test_case` 的地方）

**需要做的事情**：
- 解析菜单配置文件 `menu.js`，建立路由到端的映射关系
- 根据 `page_route` 和 `menu_path` 判断是哪个端
- 在传入 `generate_test_case` 的参数中增加 `company_type` 字段

**关键发现**：菜单配置文件 `menu.js` 中有明确的注释和常量名标识端：
- `// 供应商菜单` + `export const SPY_ORDER_MENU` → **SPY端**
- `// 核心企业菜单` + `export const CORE_ORDER_MENU` → **CE端**
- `// 资金方` + `export const CPT_ORDER_MENU` → **CPT端**

**菜单解析工具函数**（新增）：

```python
def parse_menu_config(menu_file_path: str) -> Dict[str, List[str]]:
    """
    解析菜单配置文件，建立路由到端的映射关系
    
    Args:
        menu_file_path: 菜单配置文件路径（如 menu.js）
        
    Returns:
        字典，格式：{路由: [端类型列表]}
        例如：{
            '/orderPaymentManageBook': ['SPY', 'CE'],
            '/orderPaymentManageBookCPT': ['CPT'],
            '/paymentManagementCE': ['CE']
        }
    """
    route_to_company_types = {}
    
    # 读取菜单配置文件
    with open(menu_file_path, 'r', encoding='utf-8') as f:
        content = f.read()
    
    # 当前解析的端类型
    current_company_type = None
    
    # 按行解析
    lines = content.split('\n')
    for i, line in enumerate(lines):
        # 识别注释中的端类型
        if '// 供应商菜单' in line:
            current_company_type = 'SPY'
        elif '// 核心企业菜单' in line:
            current_company_type = 'CE'
        elif '// 资金方' in line:
            current_company_type = 'CPT'
        
        # 识别常量名中的端类型（作为备用判断）
        if 'SPY_ORDER_MENU' in line:
            current_company_type = 'SPY'
        elif 'CORE_ORDER_MENU' in line:
            current_company_type = 'CE'
        elif 'CPT_ORDER_MENU' in line:
            current_company_type = 'CPT'
        
        # 解析路由（url字段）
        if current_company_type and 'url:' in line:
            # 提取路由路径，例如：url: "/orderPaymentManageBook"
            import re
            match = re.search(r'url:\s*["\']([^"\']+)["\']', line)
            if match:
                route = match.group(1)
                if route not in route_to_company_types:
                    route_to_company_types[route] = []
                if current_company_type not in route_to_company_types[route]:
                    route_to_company_types[route].append(current_company_type)
    
    return route_to_company_types
```

**判断逻辑**：
1. **优先通过菜单配置文件解析**：
   - 解析 `menu.js` 文件，根据注释和常量名识别端
   - 建立完整的路由到端的映射表
   
2. **根据路由判断端**：
   - 如果路由是 `/orderPaymentManageBookCPT` → CPT端
   - 如果路由是 `/paymentManagementCE` → CE端
   - 如果路由是 `/orderPaymentManageBook` → 可能是SPY或CE（需要结合菜单名称）

3. **结合菜单名称判断**（当路由对应多个端时）：
   - 菜单名称是"还款管理" → SPY端（在SPY_ORDER_MENU中）
   - 菜单名称是"融资还款" → CE端（在CORE_ORDER_MENU中）
   - 菜单名称是"付款管理" → CE端（在CORE_ORDER_MENU中）

4. **如果无法确定**：
   - 可以生成多个测试用例（每个端一个）
   - 或者在测试用例中标注"需要手动确认端类型"

def generate_test_cases_batch(self, api_calls: List[Dict[str, Any]]) -> List[TestCase]:
    """
    批量生成测试用例
    
    Args:
        api_calls: API调用信息列表，每个元素包含：
            ...
            - company_type: 端类型（可选）'SPY', 'CPT', 'CE'
            - company_type_name: 端名称（可选）'供应商端', '资金方端', '核心企业端'
    """
    test_cases = []
    
    for call in api_calls:
        try:
            # 如果 company_type 是列表（一个API被多个端调用），为每个端生成一个测试用例
            company_types = call.get('company_type', [])
            if isinstance(company_types, str):
                company_types = [company_types]
            
            if not company_types:
                # 如果没有指定端，生成一个通用测试用例
                company_types = [None]
            
            for company_type in company_types:
                company_type_name = self._get_company_type_name(company_type)
                
                test_case = self.generate_test_case(
                    api_method=call.get('api_method', 'GET'),
                    api_path=call.get('api_path', ''),
                    component_name=call.get('component_name', 'Unknown'),
                    file_path=call.get('file_path', ''),
                    line_number=call.get('line_number', 0),
                    call_type=call.get('call_type', 'axios'),
                    has_frontend_call=True,
                    trigger_element=call.get('trigger_element'),
                    trigger_text=call.get('trigger_text'),
                    page_route=call.get('page_route'),
                    menu_path=call.get('menu_path'),
                    call_count=call.get('call_count', 1),
                    is_core_business=call.get('is_core_business', False),
                    # 新增参数
                    company_type=company_type,
                    company_type_name=company_type_name
                )
                test_cases.append(test_case)
        except Exception as e:
            logger.warning(f"生成测试用例失败: {e}, API调用: {call}")
    
    return test_cases

def _get_company_type_name(self, company_type: str) -> str:
    """获取端的显示名称"""
    mapping = {
        'SPY': '供应商端',
        'CPT': '资金方端',
        'CE': '核心企业端'

**方法2：根据路由和菜单路径识别端类型**

```python
def _identify_company_type(self, page_route: str, menu_path: str) -> List[str]:
    """
    根据路由和菜单路径识别端类型
    
    优先使用菜单配置文件解析的结果，如果没有则使用备用规则
    
    Args:
        page_route: 页面路由
        menu_path: 菜单路径
        
    Returns:
        端类型列表，如 ['SPY', 'CE'] 或 ['CPT']
    """
    # 1. 优先使用菜单配置文件解析的结果
    if hasattr(self, 'route_to_company_types') and page_route:
        if page_route in self.route_to_company_types:
            company_types = self.route_to_company_types[page_route]
            # 如果路由对应多个端，尝试通过菜单名称进一步判断
            if len(company_types) > 1 and menu_path:
                # 例如：'/orderPaymentManageBook' 对应 ['SPY', 'CE']
                # 如果菜单名称是"还款管理"，应该是SPY
                # 如果菜单名称是"融资还款"，应该是CE
                if '还款管理' in menu_path:
                    return ['SPY'] if 'SPY' in company_types else company_types
                elif '融资还款' in menu_path:
                    return ['CE'] if 'CE' in company_types else company_types
            return company_types
    
    # 2. 备用规则：硬编码的映射（如果菜单配置文件解析失败）
    route_mapping = {
        '/orderPaymentManageBookCPT': ['CPT'],
        '/paymentManagementCE': ['CE'],
        '/paymentManagementCPT': ['CPT'],
    }
    
    if page_route in route_mapping:
        return route_mapping[page_route]
    
    # 3. 通过菜单名称判断（备用）
    if menu_path:
        menu_mapping = {
            '还款管理': ['SPY', 'CPT'],  # 需要结合路由进一步判断
            '融资还款': ['CE'],
            '付款管理': ['CE'],
            '核企付款管理': ['CPT'],
        }
        for menu_name, company_types in menu_mapping.items():
            if menu_name in menu_path:
                return company_types
    
    # 4. 如果无法确定，返回空列表（调用方需要处理）
    return []
```
